# Point & Read (포리)

포리는 난독증이 있거나 글을 읽는 데 어려움을 겪는 사람이 인쇄물에서 필요한 내용을 듣도록 돕는 안드로이드 읽기 보조 앱입니다.

## 주요 기능

- 검지 끝으로 글을 가리키면 손끝에 동그라미가 나타납니다. 끝마디만 보일 때는 관찰된 윤곽에 하늘색 선이 표시됩니다. ‘손끝 표시’를 꺼도 줄 선택과 음성은 동작합니다.
- 손끝 근처의 글줄을 강조하고, 잠시 안정적으로 가리키면 한국어 음성으로 한 번 읽습니다.
- 화면을 눌러 글줄을 선택할 수 있고, 음성을 일시정지하거나 다시 재생할 수 있습니다.
- 첫 실행 시 화면과 음성으로 사용법을 안내합니다.
- ‘읽은 글’ 탭에서 끝까지 들은 글을 다시 보거나 들을 수 있습니다. 개별 삭제와 확인 후 전체 삭제를 지원합니다.
- 카메라 영상과 글 인식은 기기 안에서 처리합니다. 기록에는 읽기를 마친 문장과 시각만 남습니다. 기록은 앱의 백업 제외 폴더에 저장합니다.

## 실행 환경

- Android 9 (API 28) 이상
- Android SDK Platform 37.0, Build Tools 37.0.0
- Android Studio 내장 JDK

## 빌드

저장소를 내려받은 뒤 Android Studio에서 프로젝트를 열고 Gradle 동기화를 완료합니다. USB 디버깅을 켠 안드로이드 휴대폰을 연결하고 Run을 누르면 설치할 수 있습니다.

명령줄에서는 프로젝트 폴더에서 다음 명령을 실행합니다.

```sh
./gradlew :app:assembleDebug
```

Windows에서는 `gradlew.bat :app:assembleDebug`를 실행합니다. APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다. 첫 빌드에는 Gradle 의존성을 내려받기 위한 인터넷 연결이 필요합니다.

`./gradlew :app:testDebugUnitTest`로 손끝 검출 시험을 실행할 수 있습니다. 손바닥 없이 둥근 끝만 움직이는 경우, 잠깐 가려졌다 다시 나타나는 경우와 손끝 후보가 여러 개이거나 직선 경계만 있는 경우를 확인합니다.

## 인식 및 음성

CameraX에서 후면 카메라 영상을 미리보기와 같은 영역으로 자르고 회전합니다. 손 모델이 검지 끝을 찾으면 그 위치를 사용합니다. 이때 모델이 마지막 관절의 가시성도 제공하고 해당 지점이 화면 안에 있으면 손끝과 관절 사이를 선으로 연결하고 관절에 작은 네모를 표시합니다.

끝마디만 보이는 장면에서는 배경과의 색 차이, 양옆의 폭과 둥근 경계를 검사합니다. 흰 종이나 어두운 바탕이 화면의 상당 부분을 차지하면 밝기 차이로도 손가락의 윤곽을 찾습니다. 손가락 부분이 화면 가장자리와 떨어져 있으면 끝마디 안쪽 여러 지점에서 명암 변화가 보이는지도 확인합니다. 이때 가는 잉크 획을 걸러 내고, 손끝 가장자리의 원래 화소를 확인합니다. 끝마디 하나만 보이면 어느 손가락인지 판별하는 데 한계가 있습니다.

연두색 점은 이번 프레임에서 찾은 손끝입니다. 형태가 잠깐 가려질 때는 직전에 확인한 손끝의 앞쪽과 양옆 모습을 현재 영상에서 다시 찾습니다. 이 경우 최대 0.18초 동안 주황색 점과 ‘손끝 움직임 추적 중’이 표시됩니다. 후보가 모호하거나 손이 사라지면 점을 숨깁니다. 일부 가려진 장면에서 손 관절의 위치를 추정해 그리는 기능은 없습니다.

ML Kit의 기기 내 한국어 OCR은 같은 카메라 영상으로 별도 작업에서 시작합니다. 글자가 없는 상태에서도 손끝을 확인할 수 있습니다. 화면의 글줄을 누르면 손끝 없이도 낭독합니다. 자동 낭독은 OCR을 시작한 프레임과 최신 프레임의 손끝이 같은 줄을 가리키고 중간에 그 줄을 벗어나지 않았을 때 시작합니다. 두 글줄이 비슷하게 가깝거나 손끝의 움직임만 추적 중이면 새 문장의 낭독을 보류합니다.

1. 한글 인쇄물을 비추고 검지 끝을 읽을 줄 바로 아래에 둡니다. ‘손끝 표시’를 켜고 동그라미가 손톱 앞의 둥근 끝을 따라가는지 확인합니다. 끝마디만 보일 때는 ‘손끝 윤곽 인식됨’이 표시됩니다.
2. 읽을 줄 바로 아래를 가리키고 잠시 멈춥니다. 강조된 줄이 한 번 들리면 다른 줄을 가리켜 봅니다. 손을 찾기 어려우면 화면의 글줄을 누릅니다.
3. 소리가 들리지 않으면 화면의 음성 상태와 기기 미디어 음량을 확인합니다. ‘음성 설정 열기’ 안내가 나오면 기기의 TTS 설정에서 오프라인 한국어 음성을 설치하거나 해당 음성을 제공하는 엔진을 선택하고 앱으로 돌아옵니다.
4. 한 줄을 끝까지 들은 뒤 ‘읽은 글’을 엽니다. 앱을 다시 열어도 문장과 시각이 남고, 기록에서 다시 들어도 항목이 늘지 않습니다. 중지하거나 다른 줄로 전환해 재생이 끊긴 문장은 저장하지 않습니다.

휴대폰 없이 시험할 때는 Android 에뮬레이터의 후면 카메라에 웹캠을 연결하거나, 검지와 인쇄물이 함께 나오는 영상을 입력할 수 있습니다. 예를 들어 SDK의 `emulator -avd PoriPreview -camera-back "videofile:/path/to/pointing.mp4"`에서 가상 기기 이름과 영상 경로를 바꿔 실행합니다. [Android 에뮬레이터 카메라 입력 옵션](https://developer.android.com/studio/run/emulator-commandline#startup-options)

끝마디가 아주 작거나 손끝 자체가 화면 밖에 있으면 윤곽을 찾기 어렵습니다. 강한 그림자, 색조명, 피부와 비슷한 색의 배경은 놓침을 유발할 수 있고, 손가락을 닮은 유색 물체는 손끝으로 잘못 잡힐 수 있습니다. 화면을 눌러 원하는 줄을 직접 고를 수 있습니다. 작거나 흐릿한 글, 촘촘한 줄, 손가락에 가려진 글자는 문장 인식에도 영향을 줍니다. 한국어 오프라인 음성과 미디어 음량은 휴대폰에서 확인해 주세요.


## 1.0.3에서 확인한 범위

- 제공된 나무 책상 사진을 480 × 640으로 줄인 입력에서 검출점은 눈으로 표시한 손끝 기준점과 약 5픽셀 떨어져 있었습니다. 같은 사진을 회전하고 좌우로 뒤집은 8개 입력에서도 기준점과의 거리가 13픽셀 미만이었습니다.
- 배경과 잉크색, 손끝 크기, 이동 속도를 바꾼 합성 시험에서 처음 감지에 쓰는 프레임을 제외한 88개 위치를 비교했습니다. 손끝 반지름의 55%에 1픽셀을 더한 범위에 들어온 횟수는 1.0.2에서 20회, 1.0.3에서 88회였습니다. 이는 정해진 시험 장면에서의 비교입니다.
- 실제 손끝 사진을 흰 바탕의 빨간 한글 위에서 움직이도록 합성해 에뮬레이터의 후면 카메라에 입력했습니다. 첫 줄에서 멈춘 뒤 두 번째 줄로 옮겼을 때 한국어 TTS 완료 기록이 각각 한 번 남았습니다. 손끝 표시를 꺼도 두 번째 줄을 선택했고, 손이 사라진 장면에서는 화면 터치로 읽을 수 있었습니다.
- 실제 휴대폰의 카메라 노출 변화, 움직임에 따른 흐림, 피부색·광원·인쇄물 조합별 성공률과 스피커 출력은 실기기 시험이 필요합니다.

손끝 측정과 추적은 `PartialTipDetector.java`와 `TipPatch.java`, 카메라와 두 분석 작업은 `CameraReader.java`와 `FrameReader.java`에서 처리합니다. 화면 상태와 낭독 선택은 `MainActivity.java`, `PointingSelection.java`, `ReaderOverlay.java`에서 다룹니다. 자동 시험은 `PartialTipDetectorTest.java`와 `FingertipMotionTest.java`에 있습니다.

## 손끝 전용 모델을 추가할 때

1.0.3에 포함된 손 모델은 손바닥 검출과 손 랜드마크 추정을 사용하는 MediaPipe Hand Landmarker입니다. 끝마디를 위한 별도 학습 데이터셋이나 학습된 가중치는 프로젝트에 없습니다. 현재 부분 손끝 경로는 관찰한 윤곽과 연속 프레임의 화소를 사용합니다. [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)

1. 별도 동의를 받아 실제 휴대폰으로 여러 사람의 검지 끝마디가 나오는 연속 영상을 준비합니다. 흰 종이의 빨간 글씨와 검은 글씨, 어두운 배경, 나무 무늬, 그림자, 좌우 방향, 촬영 거리와 이동 속도를 바꿉니다. 손이 없는 장면, 손끝이 화면 밖으로 나간 장면, 손가락을 닮은 물체도 포함합니다.
2. 프레임별로 보이는 손끝의 유무, 맨 앞 피부 경계의 정규화 좌표 `[x/너비, y/높이]`, 보이는 검지 영역의 다각형을 표시합니다. 손끝이 가려졌으면 좌표 라벨을 비웁니다. 같은 사람이나 같은 연속 영상의 프레임은 한 데이터 분할에만 넣습니다.
3. 경량 영상 모델을 손끝 위치 히트맵, 손끝 유무, 보이는 손가락 영역 마스크를 출력하도록 학습합니다. 동의받은 별도 시험 영상에서 손끝 오차, 손이 없는 프레임의 잘못된 점, 위치를 놓친 시간과 재검출 지연을 측정합니다.
4. 학습한 TensorFlow 모델을 SavedModel로 내보내고 LiteRT 변환기로 `.tflite` 파일을 만듭니다. 변환 전후 같은 입력의 출력과 지연을 비교한 뒤 검증한 파일을 Android 앱의 `assets`에 넣습니다. 기기 내 추론 입력은 현재 카메라의 회전·크롭이 적용된 RGB 영상입니다. 비율을 유지해 축소하고, 출력 히트맵과 마스크에서 패딩과 축소를 역변환해 현재 프레임 좌표로 돌립니다. `FrameReader`에서 모델의 손끝 유무 출력과 시험 데이터로 정한 기준을 통과한 경우에만 그 좌표를 사용합니다. [LiteRT 모델 변환 안내](https://developers.google.com/edge/litert/conversion/tensorflow/overview)
